# Sorting Algorithms Benchmark

## Goal
Compare five sorting algorithms in Java on four input patterns with `N = 100,000`:
- **Random**
- **Reversely sorted** (descending)
- **Partially sorted (80%)**: the first 80% is ascending; the remaining 20% contains random integers
- **Fully sorted** (ascending)

Algorithms: Selection Sort, Insertion Sort, Bubble Sort, Merge Sort, and Quick Sort.

## Requirements
- Java JDK 11 or newer (the code uses `String.repeat`).
- No external Java libraries.

## Run
```bash
javac SortingAlgorithmsBenchmark.java
java SortingAlgorithmsBenchmark
```

The default size is 100,000. For a quick correctness check, run:
```bash
java SortingAlgorithmsBenchmark 10000
```

The program prints a formatted timing table and saves the same measurements in `benchmark_results.csv`.

## Measurement method
Each algorithm receives a fresh copy of the original input array so one algorithm cannot benefit from a previous algorithm's modifications. The measured section uses `System.nanoTime()`:
```java
long startTime = System.nanoTime();
sorter.sort(testArray);
long endTime = System.nanoTime();
long durationInMicroseconds = (endTime - startTime) / 1000;
```
The program also checks that each resulting array is sorted. Times are reported in microseconds (`us`). Measurements vary with CPU, Java version, and system load, so use the results produced by your own computer in the submitted report.

## Complexity summary

| Algorithm | Best case | Average case | Worst case | Extra space |
|---|---:|---:|---:|---:|
| Selection Sort | O(N²) | O(N²) | O(N²) | O(1) |
| Insertion Sort | O(N) | O(N²) | O(N²) | O(1) |
| Bubble Sort (early exit) | O(N) | O(N²) | O(N²) | O(1) |
| Merge Sort | O(N log N) | O(N log N) | O(N log N) | O(N) |
| Quick Sort (random pivot) | O(N log N) expected | O(N log N) expected | O(N²) | O(log N) expected stack |

## Analysis / discussion
- **O(N²) vs O(N log N):** for large arrays, the quadratic algorithms perform dramatically more comparisons/moves. Increasing N by a factor of 10 can increase quadratic work by roughly 100 times, while N log N algorithms grow much more slowly.
- **Selection Sort** performs about the same number of comparisons regardless of input order, so sorted input does not make its running time linear.
- **Insertion Sort** and **Bubble Sort with early exit** can be fast on fully sorted input. Reverse-sorted data is a difficult case for both because many shifts/swaps are required.
- **Merge Sort** has predictable O(N log N) time across the four patterns, at the cost of O(N) extra memory.
- **Quick Sort** usually performs well with a randomized pivot. A poor pivot can create highly unbalanced partitions and O(N²) time; randomizing the pivot reduces the chance that a fixed input order consistently triggers that behavior, but does not remove the theoretical worst case.
- **Partially sorted case:** results depend on the precise definition of “80% sorted.” This project explicitly sorts the first 80% and fills the remaining 20% with random values, making the experiment reproducible.

## Chart
After running the Java benchmark, create a grouped bar chart from the generated CSV using Python and Matplotlib:
```bash
python plot_results.py
```
The script creates `benchmark_chart.png`. Include the chart and the actual console table in the GitHub report/README after running the full required test.

## Important note about N = 100,000
Selection, insertion, and bubble sort have quadratic worst-case behavior. At 100,000 elements, some cases—especially reverse-sorted input for insertion sort and bubble sort—can take a very long time. If you need a quick correctness check, first run with `10000`; use the required default run for final benchmark measurements and allow it enough time to finish.
